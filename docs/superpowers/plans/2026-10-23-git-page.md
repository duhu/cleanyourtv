# Git page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fourth Home page showing the 30-day commit panorama of the GitLab projects the TV's token can see, fed by `StandbyFeed`, with the status bar's CI cells taken from the same discovery.

**Architecture:** `GitData` (pure Java) parses GitLab's projects and commits answers into `Repo`s and a sorted `Snapshot`; `StandbyFeed` gains a `fetchGit` runnable that runs discovery, commits and pipelines every 10 minutes and publishes the snapshot inside `StandbySnapshot`; `GitPageView` draws it with a shared `BarChartView`. The theme scripts merge a gitignored `config.local.json` so the token never reaches git.

**Tech Stack:** Android (Java, minSdk as today), org.json, JUnit 4 JVM tests under `launcher/app/src/test`, bash/PowerShell theme tools. Spec: `docs/superpowers/specs/2026-10-23-git-page-design.md`.

## Global Constraints

- Build from `launcher/` with JAVA_HOME = `/Users/pang/.local/opt/homebrew/opt/openjdk@17`; `./gradlew testReleaseUnitTest lintRelease assembleRelease -q --console=plain` must pass.
- Every new call into views or the feed runs under `StandbyFeature.run`; parsers never throw.
- Constants: `GitData.DAYS = 30`, `CANDIDATES = 12`, `SHOWN = 8`, `MAX_PAGES = 5`, `PAGE = 100`; `StandbyFeed.GIT_MS = 10 * 60_000L`.
- Tiers from the last 7 days: `>= 10` HOT, `>= 1` WARM, else COLD.
- No token in git: `themes/*/config.local.json` is ignored; the committed theme keeps `REPLACE_ME`.
